# Germany

The original shared [Oracle Candidate Experience reader](../../shared/oracle/README.md)
qualifies JPMC's external CX_1001 site, including its native Germany location
partition. It preserves complete public job sections and distinct identities,
with checked inner job pagination and no role-query acquisition. Other
employers and external sites require independent qualification.

The Germany package consolidates original StepStone implementation and the maintained BA derivative, including its nine existing job/salary/education/training/coaching tools. Country tools are applicant-neutral and preserve original source evidence.

- [arbeitsmarkt/](arbeitsmarkt/): structured Jobsuche v6 list, full v4 detail and all workplaces/dates, with salary, Ausbildung, study, training and coaching families. Original Greyt GmbH distribution and notices remain intact. Five retained non-job families require their own current live verification; jobs success does not certify them.
- [stepstone/](stepstone/): independent complete HTML/native-record parser, current robots-aware HTTP access, exact geography/query preservation, resumable checkpoints and explicit errors. The new module entrypoint and read-only annotations make the same implementation available through the unified MCP.
- [student-boards/](student-boards/): original Jobmensa public list/detail reader, exact native partitions and pagination, current robots checks, complete native structured descriptions and explicit source limits. Its three read-only tools run through [public-services/](public-services/), alongside the credential-gated Interamt API.
- Shared ATS, native public feeds and full snapshot/detail retrieval are registered once; country eligibility is not inferred from a global feed label.

For vacancy inventory, BA work, internship, apprenticeship and self-employment offerings are distinct partitions. Native age filters are not exact publication instants, resolved geography must be inspected, and distance ordering does not justify early date stopping.

The German universe register also includes public-sector/state/municipal portals, major/local/specialist boards, universities/research/hospitals, students/apprenticeships, staffing, direct-employer discovery and freelance client demand. Statistical context and education/training remain separate from vacancies. These branches are not silently reduced to BA or StepStone.

Original additional adapters are still required for the registry's research entries. Interamt and Karriere.NRW publish API surfaces; access/authorization must be established rather than defaulting to browser scraping. Account matching platforms and denied routes remain explicit external limits. [Coverage](../../docs/coverage.md) identifies the exact gap categories.

Original shared [d.vinci publication tools](../../shared/dvinci/README.md) read

The original shared [Jobshop career reader](../../shared/jobshop/README.md)
qualifies Fraport's complete native SSR link array and primary CMS adverts,
separate from the SuccessFactors profile portal, source clocks and form text.
Other employers and historical supply remain explicit qualification gaps.

The original shared [SAP RMK reader](../../shared/successfactors/README.md)
adds a verified native Germany partition, complete descriptions and checked
continuation on SAP's explicitly linked legacy career board. The separate new
SAP front and other employers remain discovery requirements; source labels and
posted dates do not establish individual eligibility or historical coverage.

The original far_retail public-board module reads the fixed Frankfurt Airport
Retail company inventory and complete native primary/CMS text through the
existing German board tools. Whole counts, exact IDs and separate benefits/
company context reconcile; source experience labels and monthly hours remain
raw. No hydration credential or application operation is used.


## Modern SAP careers front

The original sap_modern reader uses the existing German public-board tools,
separately from the legacy SAP SuccessFactors RMK reader. Its fixed board is
https://jobs.sap.com/en/jobs/; the advertised native Germany facet is
https://jobs.sap.com/en/jobs/?country=Germany. Follow each actual next page
and preserve the first native total. No role, experience, department, custom
sort or candidate query is exposed. A whole current front is not a frozen
week, national market or complete employer census.

The source serves both inline and cached React Flight frames. The original
data-only parser checks byte lengths, explicit stream start/closure, separate
record namespaces and resolved model agreement. It never evaluates website
scripts or modules. The public native default newest sort, page, size, query
echo, counts and unique posting IDs must reconcile.

Full primary HTML is retained independently of schema descriptions and generic
page context. URL IDs differ from requisition references. Posting/display
clocks, part/full-time and work-pattern labels remain raw; there is no exact
student contract, original-publication, worker-country or applicant-fit claim.
Runtime reads only anonymous first-party public HTML and robots. No source
script, image, account, application, personalization or contact request.

Protocol facts were checked against the
[public React 19.2 client protocol](https://github.com/facebook/react/blob/v19.2.0/packages/react-client/src/ReactFlightClient.js).
This is an original Python data reader; source website and framework code are
not executed or copied into the implementation. Source-specific native and
installed qualification receipts are recorded separately from unit tests.

The original JOIN public employer-board inventory and full-primary reader is included through the existing `de_public_german_board_inventory/detail` tools. It preserves both SSR variants, special general-application pagination and distinct native/public job identities. [Contract](../../docs/join-native-reader.md).
